# Responsive Layout

## Overview

The site uses a CSS grid layout with a three-tier breakpoint scale and fluid typography via `clamp()`. **The desktop Mondrian composition has a width floor of 1024 CSS px and a height floor of 960 CSS px**—it renders while the viewport is at least 1024px wide AND at least 960px tall, and below either floor the page uses the responsive composition instead. Above the floor it is capped at `--mondrian-max-width` (1280px) so very wide viewports center the composition with symmetric gutters. Below it, the page swaps to a vertical stack, edge-to-edge under 1024px of width and capped at 1024px above it. Three of the four focus states (about, projects, connect) size their focused panel to its measured content via JS-measured `--cell-h-{about,projects,connect}` CSS custom properties; community-focus uses minmax-only sizing because Connect lives on a track community would absorb. See #330.

## Requirements

1. The `.mondrian` grid uses `display: grid` with explicit column and row templates.
2. On viewports at least 1024px wide **and** at least 960px tall, the grid layout is active with `aspect-ratio: 1 / 1`.
3. The Mondrian composition's width is capped at `--mondrian-max-width` (1280px); above the cap it centers with symmetric left/right gutters.
4. Below 1024px wide or 960px tall (`@media (max-width: 1023px), (max-height: 959px)`), the media query prevents panel interactions (JS guards) and the layout becomes a vertical stack. It has no max-width and no horizontal gutters below 1024px of width, its original case; a stack reached by the height axis on a wider viewport is capped at 1024px and centered (`@media (min-width: 1024px) and (max-height: 959px)`), because edge-to-edge at 1440px set the body copy to a 1378px measure. The JS guard in `src/pages/index.astro` matches the same two-axis condition, and `tests/desktop-composition.test.js` asserts in a real browser that ordinary desktop windows get the composition and that the pixel under each floor gets the stack.
5. Typography uses `clamp()` for fluid scaling (e.g., `clamp(0.8rem, 1.1vw, 1.08rem)`).
6. The stage centers content with `display: grid; place-items: center`.
7. The breakpoint scale is documented as CSS custom properties on `:root`:
   - `--bp-narrow` (480px)—phone-portrait threshold (project pages, metadata strips, 404 page).
   - `--bp-tablet` (768px)—phone-landscape / tablet-portrait threshold.
   - `--bp-stack` (1024px)—homepage Mondrian-to-stack swap, width axis.
   - `--bp-stack-height` (960px)—homepage Mondrian-to-stack swap, height axis (requirement 12).
   - `--mondrian-max-width` (1280px)—wide-viewport composition cap.
   See #313 (initial scale) and #330 (formalisation + bio-block content-sizing).
8. In about-focus and projects-focus, the spanning panel's first content track equals the JS-measured content height (`--cell-h-about`, `--cell-h-projects`), and the helper line + second content track collapse to 0. The right column's row tracks below retain their proportional sizes—the columns no longer share heights.
9. In connect-focus, track 8 equals the JS-measured Connect content height (`--cell-h-connect`); other tracks remain at their proportional minmax sizes. Connect's panel cell is therefore exactly content-sized—no cream void below the link list and "FROM THE BLOG" footer.
10. Community-focus does NOT apply the absorbed-helper pattern: Connect's `grid-row: 8` lives on a track that Community would absorb, and prior attempts to keep both content-sized (#325–#327) failed to converge. Community-focus uses minmax-only proportional sizing across all tracks; Connect renders as a tall narrow tile on the right. See #329 / #330.
11. The Selected Projects footer carries a `DOMAINS` eyebrow label on its ribbon row, beside the `View all projects` exit, and its content line below reads `Consumer · Enterprise · Finance · Developer tooling`—the label is a sibling element, not the first term of the line. The line is built from the `PROJECT_DOMAINS` array in `src/pages/index.astro` with a non-breaking space inside each multi-word term so a term never splits across the ribbon's two possible lines. The intro paragraph does not name the domains—the footer does—so they are said once rather than twice. The ` · ` separators are literal text rather than generated content, which is what lets a `Range` measure the line as a reader sees it. Measured: the line sets on one line at every viewport from 390px to 2560px and occupies at most 0.517 of the ribbon at desktop (at the 960px-tall height floor; 0.481 at the width floor), against 0.986 for the ten-item stack line it replaced. The width at which it clears the exit link's column is not a breakpoint of its own—it is a consequence of the composition's height floor (requirement 12). The exit link takes ~136px of the row above, and the tightest ribbon the composition renders is 626.4px, at the 912px square of a 1440×960 window, where the line clears by 165.9px. It clears at every desktop geometry, so `tests/projects-ribbon.test.js` asserts clearance unconditionally and carries no exemption list. Until #992 it did not clear at 1280×700 (−33.1px), and that failure is what established the floor rather than something the footer was asked to absorb. #984 shipped this behind a build-time switch against a `STACK` alternative so the two could be compared live; #991 settled it on DOMAINS and deleted the switch, the losing branch, and the #930 degradation ladder that only `STACK` used. The stack itself is not lost—it is on every project page and on the résumé. See #984, #991.
12. **The desktop Mondrian composition has a height floor of 960 CSS px** (`--bp-stack-height`), alongside the 1024px width floor. The square is `min(95vw, 95vh, --mondrian-max-width)`, so a short window shrinks it as a narrow one does, and at every width from 1280 to 2560 the panel geometry is a function of viewport height alone. The floor is the lowest height at which no open panel's own text is clipped by the grid (`.mondrian` is `overflow: hidden`), measured on the built page with each panel opened by a real hover. About binds: its content track is its measured text height (`--cell-h-about`), so its text runs past the grid's bottom edge below 942px tall (2px at 940, 110px at 900, 167px at 840). 960 leaves 17px, just under one reflowed line. The other limits are lower: Projects' text clips below about 875px, Community's content overflows its own panel below 824px, and Projects' `DOMAINS` line meets its exit link at 740px (0.1px clearance) and runs under it below. At 1280×700 it runs 33.1px under, the defect #992 was filed about. Community's `SCOPE` line wraps from one line to two between 960px and 900px tall; it has no exit link beside it, so the wrap collides with nothing. Connect's `LATEST POST` line is not governed by this floor: it runs under its exit link at every geometry, because its content is the latest post title and its length is editorial rather than geometric.

    **Known and not solved by the floor:** with About open, the composition's bottom band (the Community strip below About) is pushed past the grid and cut: 87px at 960 tall, and 27px even at the 1024×1200 width floor, where it predates #1042. Fixing About's focus-state row model is what would let the height floor come down toward 824px; see #1044.

    **The height floor is not a mirror of the width floor.** #1003 first set it to 1024px on the reasoning that the square cannot tell which axis constrained it. That is true of the square and false of the readers: almost every desktop browser window is under 1024px tall once the browser's own tab strip and toolbar are subtracted (a maximized Chrome on a 1080p monitor is about 950–970px, a 16-inch MacBook Pro about 1000px), so from 2026-09-06 to the fix production served the phone stack to nearly every desktop visitor (#1042). Any change to this floor must keep `tests/desktop-composition.test.js` green at its real desktop viewports, including its grid-clipping assertion. See #992, #1042, #1044, and #984 for the clearance criterion.
