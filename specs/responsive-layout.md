# Responsive Layout

## Overview

The site uses a CSS grid layout with a three-tier breakpoint scale and fluid typography via `clamp()`. **The desktop Mondrian composition has a minimum viewport dimension of 1024 CSS px, on both axes**—it renders only while `min(viewport width, viewport height) >= 1024`, and below that on either axis the page uses the responsive composition instead. Above the floor it is capped at `--mondrian-max-width` (1280px) so very wide viewports center the composition with symmetric gutters. Below it, the page swaps to a vertical stack, edge-to-edge under 1024px of width and capped at 1024px above it. Three of the four focus states (about, projects, connect) size their focused panel to its measured content via JS-measured `--cell-h-{about,projects,connect}` CSS custom properties; community-focus uses minmax-only sizing because Connect lives on a track community would absorb. See #330.

## Requirements

1. The `.mondrian` grid uses `display: grid` with explicit column and row templates.
2. On viewports at or above 1024px **in both dimensions**, the grid layout is active with `aspect-ratio: 1 / 1`.
3. The Mondrian composition's width is capped at `--mondrian-max-width` (1280px); above the cap it centers with symmetric left/right gutters.
4. Below 1024px on either axis (`@media (max-width: 1023px), (max-height: 1023px)`), the media query prevents panel interactions (JS guards) and the layout becomes a vertical stack. It has no max-width and no horizontal gutters below 1024px of width, its original case; a stack reached by the height axis on a wider viewport is capped at 1024px and centered (`@media (min-width: 1024px) and (max-height: 1023px)`), because edge-to-edge at 1440px set the body copy to a 1378px measure. The JS guard in `src/pages/index.astro` matches the same two-axis condition.
5. Typography uses `clamp()` for fluid scaling (e.g., `clamp(0.8rem, 1.1vw, 1.08rem)`).
6. The stage centers content with `display: grid; place-items: center`.
7. The breakpoint scale is documented as CSS custom properties on `:root`:
   - `--bp-narrow` (480px)—phone-portrait threshold (project pages, metadata strips, 404 page).
   - `--bp-tablet` (768px)—phone-landscape / tablet-portrait threshold.
   - `--bp-stack` (1024px)—homepage Mondrian-to-stack swap.
   - `--mondrian-max-width` (1280px)—wide-viewport composition cap.
   See #313 (initial scale) and #330 (formalisation + bio-block content-sizing).
8. In about-focus and projects-focus, the spanning panel's first content track equals the JS-measured content height (`--cell-h-about`, `--cell-h-projects`), and the helper line + second content track collapse to 0. The right column's row tracks below retain their proportional sizes—the columns no longer share heights.
9. In connect-focus, track 8 equals the JS-measured Connect content height (`--cell-h-connect`); other tracks remain at their proportional minmax sizes. Connect's panel cell is therefore exactly content-sized—no cream void below the link list and "FROM THE BLOG" footer.
10. Community-focus does NOT apply the absorbed-helper pattern: Connect's `grid-row: 8` lives on a track that Community would absorb, and prior attempts to keep both content-sized (#325–#327) failed to converge. Community-focus uses minmax-only proportional sizing across all tracks; Connect renders as a tall narrow tile on the right. See #329 / #330.
11. The Selected Projects footer carries a `DOMAINS` eyebrow label on its ribbon row, beside the `View all projects` exit, and its content line below reads `Consumer · Enterprise · Finance · Developer tooling`—the label is a sibling element, not the first term of the line. The line is built from the `PROJECT_DOMAINS` array in `src/pages/index.astro` with a non-breaking space inside each multi-word term so a term never splits across the ribbon's two possible lines. The intro paragraph does not name the domains—the footer does—so they are said once rather than twice. The ` · ` separators are literal text rather than generated content, which is what lets a `Range` measure the line as a reader sees it. Measured: the line sets on one line at every viewport from 390px to 2560px and occupies at most 0.481 of the ribbon at desktop, against 0.986 for the ten-item stack line it replaced. The width at which it clears the exit link's column is not a breakpoint of its own—it is a consequence of the composition's minimum viewport dimension (requirement 12). The exit link takes ~136px of the row above, and the tightest ribbon the composition renders is 673.1px, at the 972.8px square both 1024×1200 and 1440×1024 produce, where the line clears by 212.7px. It clears at every desktop geometry, so `tests/projects-ribbon.test.js` asserts clearance unconditionally and carries no exemption list. Until #992 it did not clear at 1280×700 (−33.1px), and that failure is what established the floor rather than something the footer was asked to absorb. #984 shipped this behind a build-time switch against a `STACK` alternative so the two could be compared live; #991 settled it on DOMAINS and deleted the switch, the losing branch, and the #930 degradation ladder that only `STACK` used. The stack itself is not lost—it is on every project page and on the résumé. See #984, #991.
12. **The desktop Mondrian composition has a minimum viewport dimension of 1024 CSS px.** It renders while `min(viewport width, viewport height) >= 1024`; below that on either axis, the responsive composition takes over. This is not a new breakpoint—`--bp-stack` (1024px) already stated the floor on the width axis, and this states the same floor on the axis the composition is equally sensitive to. The square is `min(95vw, 95vh, --mondrian-max-width)`, so a short window shrinks it exactly as a narrow one does: measured, 1024×1200 and 1440×1024 both produce a 972.8px square with footer geometry identical to a tenth of a pixel, which is why one floor governs both axes. Below it the panel footers stop setting as designed, in this order—Community's `SCOPE` line wraps from one line to two between a 912px and an 855px square (viewport height 960 to 900), and the Projects clearance decays to exactly zero at a 703px square (viewport height 740) and goes negative below. Connect's `LATEST POST` line is the exception and is *not* governed by this floor: it runs under its exit link at every geometry including the floor itself (−12.0px at a 972.8px square), because its content is the latest post title and its length is editorial rather than geometric. See #992, and #984 for the clearance criterion this floor makes reachable.
