Generate cover letters grounded in approved Experience Units, with the same validation layer that guards resumes. Per PRD's resolved questions: cover letter is a first-class V1 output.

**Scope:**

1. **Functions endpoint.** `functions/src/generation/cover-letter.ts`. Exposes `generateCoverLetter(applicationId, tone?)`. Tone defaults to "direct professional"; future options (warm, technical) can live in the prompt.
2. **Prompt.** `functions/src/prompts/cover-letter-generation.md`. Four-paragraph structure:
   - Hook: why this company / this role specifically (grounded in Role + Company + optionally a Unit).
   - Relevant experience: 2–3 of the strongest approved matches.
   - Fit: one paragraph connecting Experience Units to the must-have Requirements.
   - Close: brief, direct, no sign-off gimmicks.
3. **Grounding.** Same controlled-generation pattern as resumes (#__PARENT_NUM__'s Phase 1 #c7). Every claim must carry `source_unit_ids`. Fabrication rejected by validation.
4. **Validation.** The existing validation layer from Phase 1 #c8 runs on the output. No special-case paths — if validation flags a hook sentence because no Unit supports it, that's correct behavior.
5. **Editor integration.** Application Editor renders a tab or mode switch (Resume / Cover Letter) pulling the right generated asset. Traceability chips and flag badges work identically.

**Non-goals:**
- Multiple tone presets at V1 (revisit Phase 3 if real use demands it).
- Email / message templates — those are outreach, a V2 surface.

**Verification:**
- Generated cover letter has every claim traceable via `source_unit_ids`.
- Validation flags any un-sourced hook or close sentence.
- Output feels like something Nathan would send (Nathan's sign-off on 3 real fixtures).
