Generated output has to leave the app. Three formats: PDF (most common), DOCX (what recruiters ask for), plain text (for email bodies and ATS paste-ins).

**Scope:**

1. **Export endpoint.** `functions/src/export/` — one module per format.

2. **Layout.** A single template per format driven by the structured generation output from the Phase 1 resume-generation ticket. Keep it boring and professional — the product's differentiator is not the resume template.
   - PDF via `@react-pdf/renderer` server-side (or `pdf-lib` if react-pdf's browser bundle is trouble in a Node function).
   - DOCX via `docx` (npm). DOCX needs to preserve paragraph/bullet structure so ATS parsers pick it up.
   - Plain text: deterministic markdown-to-text emit, stable line breaks.

3. **Fonts.** System stack only (no custom font embedding in V1 — keeps the function cold-start lean and the PDF size small).

4. **Storage.** Write exports to Firebase Storage under `applications/{applicationId}/{assetId}.{ext}`. Return a short-lived signed URL for download. Never expose a public URL.

5. **Editor integration.** "Export" dropdown in the Application Editor → PDF / DOCX / Text. Disabled if any validation flag is unresolved (already enforced in the Phase 1 editor ticket; this ticket just plumbs the actual export).

6. **Filename.** `{Company} — {Title} — Resume.pdf` (etc.). Company and Title from the Role.

**Non-goals:**
- Multiple templates — V1 ships one.
- Custom branding / colors — user can't theme in V1.
- LaTeX / fancy typography — boring is the goal.

**Verification:**
- Generate → export → open each format. DOCX opens cleanly in Google Docs + Word. PDF renders identically to the on-screen preview. Plain text copies cleanly into a Gmail body.
- ATS parseability: paste the DOCX and the plain text through a free online ATS parser — role + bullets come through structured.
