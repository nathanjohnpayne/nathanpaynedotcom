The third onboarding path: a free-form career dump (notes, Google Doc export, Slack brag-doc, etc.). Extraction pulls Units out; provenance ties them back to the input.

**Scope:**

1. **Onboarding input option.** "Paste long-form career text" on the Onboarding screen.
2. **Pre-processing.** Light normalization (collapse whitespace, unify quote marks, strip markdown). No structure assumed.
3. **Extraction.** Same `extractFromResume` endpoint with `source_type: "long_form"`. Prompt variant tells the model that input may be unstructured and to err on the side of more granular Units (one sentence → one Unit when in doubt) since the input lacks explicit role boundaries.
4. **Provenance.** `source_ref` is a stable hash of the input plus a character offset range; Unit Review surfaces the ref so the user can trace back to the paragraph.
5. **Confidence.** Long-form input is more error-prone than resume input; prompt should emit more `confidence_score < 0.5` Units, forcing more user review. This is correct, not a bug.

**Non-goals:**
- Multi-file upload — paste only for V1.
- Integration with Notion / Google Docs — V2+.

**Verification:**
- Paste a 1–2 page career dump → Units extracted with reasonable granularity.
- Re-run on the same input → identical `source_ref` (stable hash).
