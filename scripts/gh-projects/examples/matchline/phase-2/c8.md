# Capability Graph JSON export (portability)

Per PRD § Technical principles: "The user's Experience Units belong to the user. Export to JSON is a V1 feature, not V2."

This ticket ships that.

**Scope:**

1. **Functions endpoint.** `functions/src/export/capability-graph.ts` produces a JSON bundle for the current `owner_uid` containing:
   - Every `ExperienceUnit` (approved and unapproved, with `user_approved` flag preserved).
   - Every `Metric` (nested on its Unit, per the schema).
   - Every `UnitCluster` (with references to Units).
   - Optional: `JobRequirementUnit` + `UnitMatch` records per Role (opt-in flag — match data is per-application and large).
   - Roles, Companies, People, Applications, Interactions — the full CRM slice too. Portability means all the user's data, not just the Capability Graph.
2. **Format.** A single JSON document with a top-level version (`"schema_version": 1`). Shape matches the TypeScript types in `src/types/` so round-tripping is trivial.
3. **UI entry point.** "Export data" button in Settings (a new minimal Settings screen — or tuck under a user menu if we don't have one yet). One click → JSON download via a short-lived signed URL from Firebase Storage.
4. **Round-trip import** (nice-to-have, not blocker for this ticket). A matching `Import data` flow that reads the JSON and re-populates Firestore for the current owner, preserving UUIDs. If skipped here, file as a follow-up.
5. **Documentation.** README + `docs/architecture/` short doc describing the schema so anyone can write their own consumer.

**Non-goals:**
- CSV / Excel export — JSON is the portability format. Humans can transform if they want.
- Sharing export with another Matchline user — V1 is single-user.
- Incremental / streaming export — single-user V1 data fits in a single doc.

**Verification:**
- Export, pipe to `jq`, spot-check Unit count matches Firestore.
- File size is reasonable for a ~200-Unit user (< 5 MB).
