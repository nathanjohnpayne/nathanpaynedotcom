# LinkedIn HTML parser (view-source paste → Experience Units)

Let the user paste a LinkedIn profile view-source HTML and feed it through the Phase 1 extraction pipeline.

**Why view-source paste:** the PRD's resolved question #1 — the browser extension is V2.

**Scope:**

1. **Onboarding input option.** Add the "Paste LinkedIn HTML" option to the Onboarding screen alongside resume paste.
2. **HTML → structured career text.** Server-side (Functions) strip LinkedIn's HTML/JS boilerplate and emit a normalized text representation: sections for `experience`, `education`, `skills`, `about`. Use a deterministic parser, not an LLM — LinkedIn's HTML is stable enough that a 100-line Cheerio/JSDOM extractor is more reliable than prompting.
3. **Feed into Phase 1 extraction.** Same `extractFromResume` endpoint accepts a `source_type: "linkedin"` variant — the prompt adjusts slightly to handle LinkedIn's shorter per-role descriptions and the more-structured date fields.
4. **Provenance.** Every extracted Unit carries `source_type: "linkedin"` and a `source_ref` that identifies which section it came from.
5. **Dedup.** If a user pastes resume + LinkedIn for the same role, the extraction will produce near-duplicate Units. Offer a de-dup view in Unit Review (could be a follow-up ticket if this one runs long) — at minimum, surface a warning and skip auto-approval for likely dupes.

**Non-goals:**
- Browser extension — V2.
- OAuth'd LinkedIn import — V2.
- Live sync — explicitly out of scope.

**Verification:**
- Paste Nathan's LinkedIn view-source → extraction produces Units for every role.
- Dedup warning surfaces when resume + LinkedIn both produce a Unit for the same role.
