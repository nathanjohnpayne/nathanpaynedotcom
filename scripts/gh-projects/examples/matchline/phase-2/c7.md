Makes the Pipeline active rather than passive. Lightweight — not a task manager.

**Scope:**

1. **Data model.** Add a `Task` type: `{ id, owner_uid, application_id, title, due_at?, completed: boolean, created_at }`.

2. **Right sidebar on Pipeline.** Collapsible. Three sections:
   - **Due today** — tasks with `due_at` ≤ today, not completed.
   - **Upcoming** — tasks with `due_at` in the next 7 days.
   - **Follow-ups** — auto-generated: applications with `last_activity_at` > 7 days stale in an active stage (Applied, Interviewing). Clicking adds a proper task.

3. **Add task.** Quick-add on any card in Pipeline (`+ task` affordance) or from Role Detail. Default `due_at` is `now + 3 days` for active-stage applications.

4. **Complete task.** One-click check, optimistic UI. Completed tasks update `last_activity_at` on the parent Application.

5. **No auto-sending.** V1 does not send emails or Slack messages. Tasks are reminders; the human acts on them.

**Non-goals:**
- Calendar integration.
- Recurring tasks.
- Email/Slack notifications — explicit V2.

**Verification:**
- Manual: application sits in Applied for 8 days → follow-up surfaces automatically.
- Manual: add task from card → appears in Due today / Upcoming based on due_at.
- Firestore: task writes scoped to `owner_uid` via the service layer (per Phase 1 #c1).
