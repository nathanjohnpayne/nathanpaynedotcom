The scoring engine and the vocabularies it runs on. This is the component users judge the product by — if matches feel accurate, the rest of the product earns trust.

**Blocks on:** #__C1_NUM__ (extraction), #__C2_NUM__ (parsing). Both produce the inputs the engine scores.

**Scope:**

1. **Scoring formula.** `functions/src/matching/score.ts` (or `src/matching/score.ts` — put it wherever both Functions and the client can import; likely `functions/src/` with a tiny shared `types/` package if needed). Implement the formula from spec § Matching engine:

   ```
   final_score = confidence_score × (
     0.30 × semantic_similarity +
     0.20 × skill_overlap       +
     0.15 × domain_overlap      +
     0.10 × tool_overlap        +
     0.10 × seniority_alignment +
     0.10 × scope_alignment     +
     0.05 × recency
   )
   ```

2. **Components.** Each weight component is a pure function on (Unit, Requirement). `semantic_similarity` is cosine similarity on cached embeddings. Overlaps are Jaccard on canonical skill/tool/domain sets. Seniority and scope are penalty functions (one-level gap reduces; multi-level gap → 0). Recency is exponential decay on `date_range.end`, floored.

3. **Canonical ontology seed.** `data/ontology/{skills,tools,domains}.json`. Hand-curate ~100 tech-PM-relevant skills, tools, domains. Include synonyms. Normalize at extraction + parsing time so downstream Jaccard is a set-vs-set operation, not a fuzzy string match. Reviewable + editable by the user later.

4. **Rationale string.** Per `UnitMatch`, generate a one-sentence rationale pointing at the strongest component. Either deterministic from the scores (fast, cheap) or via `modelFor("rationale")` (better prose). Cache the rationale on the UnitMatch doc so it isn't regenerated per view.

5. **Unit tests.** One test per scoring component. Explicit fixtures covering:
   - Monotonicity: higher overlap → higher overlap score.
   - Confidence gating: `confidence_score = 0` → `final_score = 0`.
   - Seniority penalty: one-level gap reduces; multi-level gap → 0.
   - Recency floor: a 10-year-old Unit still contributes if highly relevant.

**Non-goals:**
- User-specific ontology refinement (V2).
- Nursing / finance / non-tech domain coverage (explicit non-goal in spec).
- ML-driven weight tuning — weights come from the PRD. Tuning is Phase 3.

**Verification:**
- All unit tests green.
- Match generation over 10 Units × 20 Requirements p95 ≤ 2 s (essentially pure math + vector ops once embeddings exist).
