The first step of the core loop: pasted resume text in, structured `ExperienceUnit[]` out. This is the single most important component in V1 — match quality is gated by extraction quality, and generation quality is gated by both.

**Blocks on:** #__C1_NUM__ (owner_uid + auth).

**Scope:**

1. **Functions endpoint.** Add `functions/src/extraction/index.ts` with `extractFromResume(text)` wrapped as a callable function. Uses the Anthropic client via `modelFor("extraction")` (Sonnet 4.6 per PRD).
2. **Prompt.** Under `functions/src/prompts/`, write the extraction prompt. Strict JSON schema in the system prompt; few-shot examples in the user turn; instruct the model to mark every Unit with `evidence_type` and a `confidence_score`. Prompt lives in a file, not inline.
3. **Structured output.** Use Anthropic's `tool_use` with a schema matching `ExperienceUnit` (minus `embedding`, which is generated downstream). Two retries with stricter prompts on malformed JSON; surface as `needs manual review` on third failure per spec § Execution targets.
4. **Embeddings.** After extraction, call `embedMany(units.map(u => u.normalized_summary))` and stamp the results onto each Unit before writing to Firestore.
5. **Write path.** Each Unit gets `user_approved: false` on creation — Unit Review (c3) is where it flips true.
6. **Source provenance.** Every Unit carries the `source_ref` that ties it back to the input string (e.g. a hash of the input plus a character range).

**Non-goals:**
- LinkedIn HTML and long-form context — those land in the Phase 2 LinkedIn-parser and long-form-context tickets.
- Incremental updates when the user edits the raw text — Phase 3 / tuning.

**Verification:**
- Unit test: given a known resume string, extraction produces ≥ N units where every Unit validates against the schema, `confidence_score ∈ [0, 1]`, `user_approved === false`.
- p95 latency ≤ 20 s for a typical resume.
- Cost per extraction ≤ $0.50 (logged to console for now).
