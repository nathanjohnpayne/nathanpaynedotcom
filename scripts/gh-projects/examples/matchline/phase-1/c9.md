The surface where generated output becomes something the user sends. Two-pane: generated resume on the left, approved Units on the right. Validation flags surface inline.

**Blocks on:** #__C1_NUM__ (generation) and #__C2_NUM__ (validation output to render).

**Scope** (`src/routes/ApplicationEditor.tsx` replaces the Sprint 0 placeholder):

1. **Two-pane layout.** Left: rendered resume (from the structured output of #__C1_NUM__). Right: approved Experience Units for this Application.

2. **Traceability annotations.** Each bullet carries `source_unit_ids` — render them as small inline chips after the bullet. Hovering a bullet highlights the source Unit(s) in the right pane; clicking a Unit chip scrolls the pane to it.

3. **Validation flag badges.** For every claim the validation layer flagged, show a badge on the bullet. Badge click opens a popover with the flag type (untraceable / specificity) and the rationale string. Three resolution paths:
   - Edit the bullet to tie to an existing Unit.
   - Remove the bullet.
   - Add a supporting Unit (opens Unit Review's "Add Unit manually" flow in a modal, comes back here on save).

4. **Export is blocked.** Until all validation flags are resolved, the Export button is disabled with a tooltip explaining why. This is the enforcement point for zero-fabrication — not a warning, a gate.

5. **Edit preserves traceability where possible.** Inline-edit a bullet: the editor re-runs claim extraction + traceability on the new text. Claims that become untraceable surface as new flags.

6. **Standard editing.** Add / remove / reorder bullets. Undo. Autosave.

**Non-goals:**
- PDF/DOCX export — Phase 2 export ticket.
- Cover-letter editor — Phase 2.
- Multi-version history — Phase 2+.

**Verification:**
- Playwright E2E: generate → flag appears → resolve flag via edit → export unlocks.
- Unit tests on the re-validation-on-edit flow.
- Screen-reader pass: flags and annotations are keyboard-navigable and announced.
