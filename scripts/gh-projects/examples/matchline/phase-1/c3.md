The primary surface for maintaining the Capability Graph. This is where the product's integrity claim is earned — no Unit enters matching or generation until the user flips `user_approved` to `true`.

**Blocks on:** #__C1_NUM__ (extraction produces Units to review).

**Scope** (`src/routes/UnitReview.tsx` replaces the Sprint 0 placeholder):

1. **List view.** All Experience Units for the current owner. Each row shows: `normalized_summary`, `unit_type`, approval state, `confidence_score`, source provenance string.
2. **Filters.** By skill, tool, domain, date range (from `date_range.start`/`end`), and approval status. Multi-select filters.
3. **Inline edit.** Every field on `ExperienceUnit` editable. Editing `raw_text` or `normalized_summary` invalidates the stored embedding — mark the Unit "re-embed pending" and schedule a function-backed re-embed.
4. **Approve / reject / flag.** Three buttons. Rejected Units are retained but excluded from matching (`user_approved: false` + a `rejected: true` marker or equivalent). Flagged Units appear in a review queue.
5. **Manual add.** "Add Unit manually" CTA opens a form that writes an `ExperienceUnit` with `source_type: "manual"`.
6. **Success metric.** Onboarding is "successful" when the user has ≥ 20 approved Units. Surface a small counter in the header.

**Non-goals:**
- Bulk actions (Phase 2 polish).
- Diff view for re-extractions (Phase 3).
