**The foundational ticket for Phase 1.** Everything else in this phase depends on this landing first.

**Scope:**

1. **Sign-in.** Wire Firebase Auth (Email/Password or Google per the Phase 0 auth-provider decision) through the frontend. Add a sign-in screen ahead of the app shell. Gate `/onboarding` and every protected route behind an authenticated user.
2. **Schema.** Add `owner_uid: UUID` to every object in `src/types/` (`Person`, `Company`, `Role`, `Application`, `Interaction`, `ExperienceUnit`, `JobRequirementUnit`, `UnitMatch`, `UnitCluster`).
3. **Service layer.** Implement the `ownerScope()` helper stubbed in Phase 0 to return `[where("owner_uid", "==", userId)]`, source `userId` from the current auth state. Thread it into every `list*` function. On write, every `upsert*` stamps `owner_uid` from the current user.
4. **Rules.** `firestore.rules` already enforces `resource.data.owner_uid == request.auth.uid`; confirm the rules match the query shape and extend the `isCreatingAsOwner` check to require `owner_uid` on create.
5. **Emulator tests.** Small integration test using `@firebase/rules-unit-testing` to confirm a cross-owner read is rejected and an owner-scoped read succeeds.

**Non-goals:**
- Multi-user collaboration (explicitly out of V1 scope).
- Social login providers beyond the one Firebase console flow sets up.
- Sign-up UX polish — basic form is fine.

**Verification:**
- `npm run test` passes rules-unit-testing integration tests.
- Manual smoke: signed-in user can create an ExperienceUnit; signed-out or cross-owner reads fail.
