The component that makes zero-fabrication a hard constraint, not a wish. Every generated output passes through validation before the user sees it; export is blocked until validation flags are resolved.

**Blocks on:** #__C1_NUM__ (generation produces output to validate).

**Scope:**

1. **Functions endpoint.** `functions/src/validation/validate.ts` exposes `validateAsset(assetId)`. Operates on the structured output from generation (each bullet has `source_unit_ids`).

2. **Claim extraction.** Parse every bullet + summary sentence into discrete claims. "Led migration of Disney+ playback stack to 64-bit NCP, reducing memory 30%" → three claims: (led a migration, worked on Disney+ playback on NCP, achieved 30% memory reduction). Use `modelFor("validation")` (Sonnet — claim-level precision matters more than per-token cost).

3. **Traceability check.** For each claim, verify it maps to at least one approved Unit via the bullet's `source_unit_ids`. A claim is traceable if the Unit's `raw_text` + `normalized_summary` + `metrics` semantically support it. "Supports" is a model call with a strict yes/no tool-use schema.

4. **Specificity check.** Flag generic language that doesn't tie to any Unit: "collaborated cross-functionally to drive results", "leveraged data to inform decisions". A small deny-list of vague phrasings + a model-based "is this claim specific enough to verify?" check.

5. **Flag record.** Output is a list of `{ claim, bullet_id, status: "traced" | "untraceable" | "specificity", supporting_unit_id?, rationale }`. Stored on the AssetRef.

6. **No auto-regeneration.** Per spec § Execution targets / Reliability: validation failures never auto-regenerate. They always surface to the user for explicit approval.

**Non-goals:**
- Silencing the validation layer. If the layer can't run, treat the output as unsafe and do not surface.
- Model-call-free validation (would be nice; defer to Phase 3 if a deterministic shortcut emerges).

**Verification:**
- Fixture test: a resume with one fabricated claim ("Managed a team of 40 at Netflix" when no Netflix Unit exists) produces a flag on that claim.
- Fixture test: a resume where every claim traces cleanly produces zero flags.
- p95 ≤ 3 s per spec § Execution targets.
