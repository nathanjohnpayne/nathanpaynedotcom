Cost is a PRD principle ("Cost is a feature"). Telemetry lets Nathan see when the budget slips.

**Scope:**

1. **Per-stage instrumentation.** Every LLM call records `{ stage, model, input_tokens, output_tokens, duration_ms, cost_usd, application_id?, timestamp }` to a `telemetry` collection. Already partially logged (Phase 1 #c7 asks for per-generation logging); this ticket ships the whole thing.
2. **Aggregation.** A lightweight Firestore aggregation (or a Cloud Function nightly rollup) produces daily and per-application totals.
3. **Dashboard.** A new Settings → Telemetry page or a modest admin route. Shows:
   - Total spend this month (Anthropic + OpenAI).
   - Per-application cost distribution (histogram).
   - Stage-by-stage latency p50/p95.
   - Cost vs. p95 trend chart (the two numbers that matter).
4. **Guardrail.** If a day's spend crosses $X (Nathan-configurable), the app surfaces a banner. Hard kill is out of scope — soft signal is enough for a single user.
5. **Provider spend caps.** Already a Phase 0 ticket (#c8 human action) to set spend caps at the provider level; this ticket confirms those are in place and surfaces them in the dashboard.

**Non-goals:**
- Real-time cost attribution per user — V1 is single-user.
- Automated prompt / model switching based on budget — that's a tuning decision, not a feature.

**Exit criteria:**
- Dashboard renders with at least 7 days of real data.
- Nathan can answer "how much did the last application cost?" in one click.
