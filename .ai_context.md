## Project Name
nathanpayne.com

## Project Type
Static personal portfolio, project case-study, and editorial content site built with Astro (static site generator). Outputs pre-rendered HTML/CSS/JS—no server runtime.

## Primary Languages
- Astro (`.astro` templates)
- TypeScript / JavaScript (ES modules)
- CSS3 (vanilla, custom properties)
- Markdown (blog and project content with YAML frontmatter)

### Load-bearing npm dependencies that look removable

`@astrojs/markdown-remark` is a required devDependency that **no source file imports**. It backs the `markdown.remarkPlugins` / `markdown.rehypePlugins` hooks in `astro.config.mjs`, which is how the three custom plugins in `src/plugins/` run. A dependency-graph scan will report it as unused; removing it breaks `astro build`. `astro` and `@astrojs/markdown-remark` are both pinned to the exact same version, because Astro declares the latter as an exact-version peer; they move together or not at all.

`@astrojs/mdx` is the third member of that lockstep set, added in epic #759 so a project page can place a frontmatter-driven component mid-body. It is what makes the `projects` glob `**/*.{md,mdx}` work. Its coupling is quieter than the other two: it declares **no peer** on `@astrojs/markdown-remark` but carries an **exact regular dependency** on it that differs per mdx release, so bumping `astro` and `@astrojs/markdown-remark` without a matching mdx release nests a second copy of the Markdown pipeline instead of raising ERESOLVE. All three are therefore pinned exact in `package.json`, with no caret on any of them. Separately, `typescript` is declared as the bounded range `>=6.0.3 <6.1.0`, not a caret range, because `typescript-eslint` peers `<6.1.0`. Every one of these constraints, and the procedure for changing them, is specified in `rules/repo_rules.md` § Toolchain Constraints—that file is authoritative, this note only exists so the dependencies are discoverable from the inventory.

`css-tree` is a devDependency that is **also a transitive dependency** of the Astro/Vite toolchain, and that is precisely why it is declared rather than reached for. `tests/lifecycle-marker.test.js` parses the emitted stylesheet with it—rules, selector lists, class tokens, at-rules—and a required check resting on a package that only arrives by accident stops working on the next dependency bump with no signal beyond the check going quiet. A deduplication pass will report the direct entry as redundant; it is not. Test-only, nothing ships from it. See #967 and `rules/repo_rules.md` § Toolchain Constraints.

### Build-time Mermaid dependency

`rehype-mermaid` is the maintained build-time renderer. Astro excludes Mermaid fences from Shiki, then renders them to static inline SVG in the Markdown pipeline so readers do not need Mermaid-capable browsers. Sidebar items use the same renderer and configuration through `src/lib/render-sidebar-mermaid.mjs`; the direct `vfile` dependency supplies the real file object that Rehype plugins expect. The small site-owned adapters preserve required title/description metadata, the optional visible caption, figure semantics, a clean failure fallback, and one rendered line per authored label break; they do not parse Mermaid grammar. Figure semantics here means two elements rather than one: a `<figure>` holding a `role="img"` graphic and, when authored, a `<figcaption>` outside it, so a visible caption is not made presentational by the image role (#989). That last adapter exists because `hast-util-to-html` enters the SVG schema at `<svg>` and never leaves it inside `foreignObject`, so a label's `br`—void in HTML, not in SVG—would serialize as `<br></br>` and be read back as two breaks (#788). No Mermaid runtime or CDN dependency ships to production browsers.

## Standard Compliance Notes

- **`src/` present:** Astro source directory containing pages, layouts, content collections, plugins, integrations, and styles.
- **`dist/` present but gitignored:** Build output from `astro build`. Deployed to Firebase Hosting.
- **`public/` present:** Static assets (favicons, robots.txt, OG fonts) copied verbatim into `dist/` at build time.
- **`functions/` absent:** Intentional. No serverless functions. Documented above.
- **`docs/` present:** Extended documentation (agent processes, deployment guides). Documented above.
- **`scripts/ci/` present:** CI enforcement scripts run by GitHub Actions workflows.
- **`.cursor/rules/deploy.mdc`:** Valid Cursor configuration file providing deploy context to the Cursor agent. Mirrors `DEPLOYMENT.md`.
- **`.cursor/rules/project-conventions.mdc`:** Valid Cursor configuration file providing project conventions to the Cursor agent.
